# Riesgos y bloqueos

## Riesgos principales
- información de arranque incompleta
- accesos pedidos tarde o mal definidos
- checklist poco clara
- falta de visibilidad del estado
- demasiada dependencia de seguimiento manual
- handoff confuso a operación

## Bloqueos típicos
- no tener claro qué datos y accesos son obligatorios
- no disponer de acceso al n8n real del cliente
- no tener credenciales reales de Google Sheets y Gmail
- no poder probar con un onboarding real o simulado

## Regla operativa
Si no hay prueba real de punta a punta, no debe venderse como implantado.

## Mínimo de robustez exigible
- el estado del onboarding debe quedar visible
- los bloqueos deben poder detectarse
- el equipo debe recibir aviso si falta algo crítico
- el sistema no debe depender de persecución manual constante para funcionar
