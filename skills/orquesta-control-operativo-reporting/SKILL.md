# Orquesta Control Operativo y Reporting

Usa esta skill cuando el reto principal sea saber qué está pasando, detectar desvíos y gobernar la operación con datos útiles.

No sirve para hacer dashboards bonitos sin criterio. Sirve para crear visibilidad accionable.

## Cuándo usarla

Actívala cuando el usuario pida algo como:

- controlar la operación diaria
- montar reporting para dirección
- ver cuellos de botella
- medir productividad o cumplimiento
- crear alertas
- vigilar SLAs
- unificar estados de varias automatizaciones o equipos

## Qué resuelve

Diseña un sistema de control con estas capas:

1. inventario de procesos o flujos
2. estados operativos
3. eventos y métricas
4. incidencias y excepciones
5. cuadro de mando
6. alertas
7. escalado humano
8. cadencia de revisión

## Entradas mínimas

Si faltan, pide solo esto:

- proceso o área que se quiere controlar
- sistemas donde vive la actividad
- qué decisiones se toman con ese reporting
- qué fallos o retrasos preocupan más
- quién necesita ver el dato: dirección, operaciones o ejecución

## Método de trabajo

### 1. Aclara el nivel de control necesario

Distingue entre:

- seguimiento ejecutivo
- gestión operativa diaria
- control técnico de automatizaciones

### 2. Mapea el proceso y sus estados

Define:

- inicio
- estados intermedios
- finalización correcta
- error
- bloqueo
- reintento
- escalado

### 3. Selecciona métricas útiles

Prioriza métricas que cambien decisiones:

- volumen
- tiempo
- tasa de éxito
- backlog
- SLA
- incidencias
- conversión entre etapas
- causas de fallo

### 4. Diseña el reporting

Para cada vista, indica:

- usuario destinatario
- frecuencia
- métricas
- visualización recomendada
- decisión asociada

### 5. Diseña alertas y gobierno

Incluye siempre:

- umbral
- canal de alerta
- responsable
- acción esperada
- criterio de cierre

## Salidas esperadas

Cuando uses esta skill, entrega normalmente:

1. proceso o operación a controlar
2. mapa de estados
3. KPIs y eventos a registrar
4. cuadro de mando recomendado
5. alertas y escalados
6. cadencia de revisión
7. riesgos de datos o visibilidad
8. siguiente implantación útil

## KPIs base

Usa los que encajen:

- throughput
- tareas abiertas
- backlog por estado
- tiempo medio por etapa
- SLA cumplido vs incumplido
- errores por tipo
- porcentaje de automatizaciones exitosas
- incidencias críticas abiertas

## Reglas

- No mezcles métricas ejecutivas con detalle operativo en la misma vista si eso ensucia decisiones.
- Todo indicador debe tener un uso claro.
- Si no existe un dato fiable, no finjas precisión.
- Prioriza primero estados y eventos; luego dashboards complejos.
- Si hay automatizaciones críticas, define fallback humano y trazabilidad.

## Formato de salida

Responde con mentalidad de operaciones.

Prioriza:

- mapa de control
- métricas imprescindibles
- alertas
- quick wins
- riesgos
- siguiente paso concreto
